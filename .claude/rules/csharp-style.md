# C# 코드 규칙

규칙마다 `이유:` 줄은 그 규칙이 없으면 무엇이 깨지는지를 적는다.

`TV0000` 형식의 ID가 붙은 규칙은 정적 분석기(`Tools/TopView.Analyzers/`)가 검사해 Unity Console에 경고로 띄운다. 문서에는 ID와 이유만 두고, 무엇을 어떻게 검사하는지는 분석기 코드와 경고 메시지가 정한다.

도구가 생성한 코드(Input System의 액션 클래스 등)는 이 규칙을 적용하지 않는다. 생성 코드는 고치지 않는다.

## 네임스페이스
- TV0012 네임스페이스와 폴더.
  - 이유: 파일 위치만 보고 네임스페이스를 알고, 네임스페이스만 보고 파일을 찾는다.
- 예외: `Components/`의 하위 폴더는 모두 `<접두사>.Components`로 둔다. TV0012가 이 예외를 따른다.
  - 이유: 하위 폴더는 개념 분류일 뿐이라 컴포넌트를 다른 폴더로 옮겨도 쓰는 쪽 코드가 바뀌지 않는다.

## 이름
- TV0009 줄임말 금지, TV0010 한 글자 이름 금지. 분석기는 금지 단어 목록에 있는 줄임말만 잡는다. 목록에 없는 줄임말도 쓰지 않는다.
  - 이유: 줄임말은 사람마다 다르게 줄여 읽기와 검색이 어려워진다. 중첩 반복에서 `i`, `j`는 무엇을 도는지 드러내지 않는다.
- TV0011 머리글자 약어 금지.
  - 이유: 줄임말과 같다. 약어의 대소문자 표기(`Id`, `ID`)도 흔들리지 않는다.
- TV0007 이름 형식, TV0008 bool 접두사.
  - 이유: 이름만 보고 필드인지, 지역 변수인지, 상수인지 구분한다. bool은 조건문이 문장처럼 읽힌다.

접미사: `~Entity`, `~Storage`, `~System`, `~Utility`, `~ViewSystem`, `~Record`, `~Request`, `~Command`, `~Component`, `~Definition`, `~Authoring`, `~View`, `~Entry`, `~Presenter`, `~Store`, 시간 값은 `~Ticks`.
- 이유: 이름만 보고 그 타입의 역할과 따르는 규칙을 안다. `~Ticks`는 단위가 초가 아니라 틱임을 드러낸다.

## 스타일
- TV0002 `var` 금지.
  - 이유: 타입이 보이지 않으면 struct 복사인지 참조인지 코드만 보고 구분할 수 없다.
- TV0013 파일 하나에 타입 하나, TV0014 파일 이름과 타입 이름, TV0003 중첩 타입 금지.
  - 이유: 파일 이름으로 타입을 찾는다. Unity는 MonoBehaviour와 ScriptableObject를 파일 이름으로 연결한다.
- 예외: 한 타입을 역할별로 나눌 때는 `partial`로 파일을 나눈다. TV0014 `타입이름.역할.cs`, TV0015 본 파일 `타입이름.cs`, TV0016 같은 폴더. 에디터 전용 파일은 파일 전체를 `#if UNITY_EDITOR`로 감싼다(분석기가 검사하지 않는다).
  - 이유: 큰 타입을 나눠도 같은 이름으로 묶여 한 번에 찾는다. 에디터 코드가 빌드에 섞이지 않는다.
- TV0001 익명 함수 금지. 콜백이 필요하면 메서드를 만들고 이름을 넘긴다. 예: `tween.OnComplete(EnableInteraction)`.
  - 이유: 클로저는 숨은 할당과 캡처를 만들고, 콜백이 이름 없이 숨어 흐름을 따라가기 어렵다.
- TV0017 중괄호는 다음 줄에 (Allman).
  - 이유: 형식이 하나여야 diff가 형식 차이로 흐려지지 않는다.
- TV0018 멤버 순서.
  - 이유: 어느 파일이든 같은 종류의 멤버를 같은 위치에서 찾는다.
- TV0019 컴포넌트·엔티티는 struct와 public 필드, TV0020 컴포넌트·엔티티 배열 원소는 ref로, TV0021 struct 매개변수는 ref나 in으로, TV0022 고치지 않는 ref 매개변수는 in으로.
  - 이유: 배열 원소를 값으로 꺼내면 복사본을 고쳐서 원본이 바뀌지 않는 버그가 생긴다. `in`/`ref`로 수정 여부가 시그니처에 드러난다.

## Unity
- 직렬화 필드 이름을 바꿀 때는 `[FormerlySerializedAs("이전이름")]`을 붙인다.
  - 이유: 붙이지 않으면 에디터에서 입력한 값이 사라진다.
- TV0025 구 `UnityEngine.Input` 금지.
  - 이유: 같은 입력을 두 경로로 읽으면 바인딩과 동작이 어긋난다.

## 주석
- TV0023 public 메서드 문서 주석.
  - 이유: 호출하는 쪽에서 IDE 툴팁으로 의도를 본다.
- TV0024 public 필드 주석. 분석기는 한글이 있는지만 본다. 단위와 의미를 적는다.
  - 이유: 데이터 struct의 필드 설명이 곧 설계 문서다. 단위와 의미(예: 음수면 없음)를 남긴다.
- private 멤버와 지역 변수는 필요할 때만 단다.
  - 이유: 이름으로 드러나는 것을 반복하는 주석은 코드와 함께 고쳐지지 않아 틀려진다.
