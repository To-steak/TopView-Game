# 정적 분석기 (TopView.Analyzers)

C# 코드 규칙(`.claude/rules/csharp-style.md`)을 검사해 Unity Console에 경고(`TV0001`~`TV0025`)로 띄우는 Roslyn 분석기다. 사람이 쓴 코드든 AI가 쓴 코드든 컴파일할 때 같은 규칙으로 검사한다.

```sh
dotnet build Tools/TopView.Analyzers -c Release
dotnet test Tools/TopView.Analyzers.Tests
```

- 빌드: Release 빌드가 끝나면 DLL을 `Project/Assets/Analyzers/`로 복사한다
- 테스트: 규칙별 예시 문서대로 경고하는지 검사한다

## 필요한 것

- .NET SDK: 분석기는 `netstandard2.0`, 테스트는 `net10.0`(xUnit)
- Unity 쪽: `Project/Assets/Analyzers/TopView.Analyzers.dll`의 `.meta`에 `RoslynAnalyzer` 라벨. 처음 한 번 에디터에서 붙이고, 그 뒤로는 DLL만 바뀐다

## 왜 Unity 밖에 두나

- 분석기는 Unity가 아닌 .NET 라이브러리로 빌드해야 한다. 소스를 `Assets` 안에 두면 Unity가 게임 코드로 컴파일하려 한다.
- Roslyn은 4.3.0을 참조한다.
  - 이유: Unity 6000.3의 컴파일러가 Roslyn 4.3이라, 더 높은 버전을 참조하면 Unity가 분석기를 불러오지 못한다.

## 왜 만들었나

- 처음에는 `.editorconfig`의 IDE 규칙과 ErrorProne.NET을 썼다. IDE 규칙은 IDE에서만 보이고 Unity Console에는 나오지 않아서, 규칙을 분석기로 옮기고 둘을 지웠다(`04bae22a`).
- 규칙 문서(`csharp-style.md`)에는 규칙의 ID와 이유만 두고, 무엇에 경고하고 무엇을 통과시키는지는 예시 문서가 정한다.
  - 이유: 문서로만 둔 규칙은 지켜졌는지 사람이 읽어서 확인해야 한다. 분석기로 막으면 컴파일할 때마다 확인된다.

## 테스트: 예시 문서가 곧 테스트

`Tools/TopView.Analyzers.Tests/Examples/`의 문서마다 코드 예시가 있고, 경고가 나와야 하는 줄 끝에 `// 경고: TV0006`처럼 표시한다. 테스트는 이 예시를 그대로 컴파일해 분석기가 표시한 줄에만 경고하는지 검사한다. 문서 쓰는 법은 [예시 문서 README](../TopView.Analyzers.Tests/Examples/README.md)에 있다.

- 이유: 규칙의 동작은 분석기 코드(Roslyn)가 아니라 예시 문서로 확인한다. 예시가 곧 테스트라 문서와 분석기가 어긋나지 않는다.
- `ExampleCoverageTests`가 모든 분석기와 모든 규칙 ID에 예시가 있는지 검사한다. 새 규칙을 만들고 예시를 빠뜨리면 실패한다.

## 규칙을 더하거나 바꿀 때

1. 예시 문서(`Tools/TopView.Analyzers.Tests/Examples/`)를 먼저 고친다.
2. 분석기를 예시에 맞추고 `dotnet test Tools/TopView.Analyzers.Tests`로 확인한다.
3. `dotnet build Tools/TopView.Analyzers -c Release`로 DLL을 Unity에 복사한다.
4. `.claude/rules/csharp-style.md`에 규칙의 ID와 이유를 적는다.
5. 위의 규칙 표를 고친다.

- DLL을 빌드한 직후 Unity가 domain reload를 하는 동안 다시 컴파일을 시키면 오류가 날 수 있다. 에디터가 준비된 뒤에 확인한다.
- Unity의 다시 컴파일 결과 요약에는 분석기 경고가 빠질 수 있어, `Editor.log`에서 `warning TV`를 함께 확인한다.
