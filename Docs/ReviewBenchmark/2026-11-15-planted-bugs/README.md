# 2026-11-15 심은 버그 측정

코드 리뷰 도구(`Tools/CodeReview/review.workflow.js`)가 버그를 얼마나 찾는지 재려고, 게임 코드에 버그 10개를 일부러 심고 리뷰를 세 번 돌렸다.

## 방법
- 기준 커밋은 `a16a4b78`(main)이다. 버그는 커밋하지 않은 작업 트리에 심고, 측정이 끝난 뒤 되돌렸다. 심은 내용은 `planted-bugs.patch`에 있다.
- 기능(feat) 작업이 게임 코드 전체에 흩어지는 것처럼, 버그도 Systems 5개, Utilities 2개, UserInterface 2개, Presentation 1개 파일에 흩어 심었다. 난이도는 쉬움 3, 중간 4, 어려움 3이다.
  - 쉬움: 한 줄 안에서 보이는 것
  - 중간: 다른 파일 하나를 따라가야 결과가 보이는 것
  - 어려움: 한 틱 차이, 칸 재사용(generation), 두 경로의 불일치
- 버그와 같은 파일에서 바로 모순되는 주석은 함께 고쳐, 주석만 보고 찾을 수 없게 했다(6번, 8번). 다른 파일의 주석(예: `World.cs`의 순서 주석)은 그대로 두었다.
- 기존 테스트(EditMode 30개, PlayMode 17개)는 버그를 심은 뒤에도 모두 통과했다. 그래서 이 측정은 테스트가 아니라 리뷰어를 잰다.
- 정답지(`answer-key.json`)는 리뷰가 끝날 때까지 저장소 밖에 두었다.
- 리뷰는 세 번 모두 같은 값(`review-args.json`)으로 동시에 돌렸다. 영역 설명은 정답을 가리키지 않도록 일반적인 문장으로 썼다. 상황 설명에서 git 명령을 쓰지 말라고 했고, 에이전트 기록에 git 사용과 정답지 접근은 없었다.
- run1의 A1·A2와 run3의 A2는 사용량 한도로 실패해 같은 runId로 이어서 다시 돌렸다. 이 영역들에는 심은 버그가 없어 찾은 수(재현율)에는 영향이 없다.
- 원본(`run1~3.json`)은 리뷰 도구가 낸 그대로다. 채점은 `score.json`에 있다.

## 관찰
- **놓친 것은 한 틱 차이 하나뿐이다.** 8번은 세 번 모두 놓쳤다. 지운 조건(`elapsedTicks == 0`)은 코드에 흔적이 없어서, `World.cs` 96줄의 순서 주석과 `EnemyStateChangeSystem`이 같은 틱에 상태를 바꾼다는 사실을 함께 맞춰 봐야 보인다. 리뷰어는 있는 코드의 오류는 잘 찾지만, 빠진 조건이 만드는 시점 차이는 찾지 못했다. CLAUDE.md의 "한 틱 차이 버그는 확인 방법이 테스트뿐"이라는 판단과 맞는다.
- **6번은 실행마다 결과가 갈렸다.** 마나 회복 지연은 run1에서는 B1이 호출처(`PlayerMoveInputSystem`)에서, run3에서는 B2가 `PlayerManaUtility`에서 찾았고, run2에서는 아무도 찾지 못했다. 버그 하나라도 실행에 따라 놓칠 수 있다.
- **같은 버그를 두 영역이 함께 찾는다.** 3번(재장전)은 세 번 모두 B1(`PlayerStateSystem`)과 B2(`PlayerWeaponUtility`)가 따로 적었다. run3에서는 7번을 A2도 `EnemyDefinition` 쪽에 적었다. 호출처를 따라가 읽으라는 지침 때문이고, 이슈로 옮길 때 같은 뿌리로 묶어야 한다.
- **심지 않은 곳의 지적**은 실행마다 13~19개였다(합계 47개). 대부분 low 등급의 inconsistency와 cleanup이다. 세 번 다 나온 것은 따로 확인할 만하다. 다만 이번 측정에서는 확인하지 않았으므로, 진짜 버그인지는 모른다.
  - 남은 시간을 내림해 마지막 1초 동안 `00 : 00`이 보인다 (`RemainingTimePresenter.cs:31`)
  - 처치 점수만 짝수 쪽 반올림(`Mathf.RoundToInt`)을 쓴다 (`DamageSystem.cs:116`, `EnemyDefinition.cs:17`)
  - `PlayerUnstuckSystem`이 사망 상태의 플레이어도 옮긴다
- 사망 연출 중에도 강화 화면이 열린다는 지적은 run2와 run3에서 나왔다. 사망한 플레이어를 어디서 거를지에 대한 기존 결정(HUD만 사망한 플레이어도 찾고, 강화는 거른다)에 비추어, 버그인지 의도인지 확인이 필요하다.
